# 社労士事務所OS — SharePoint / SPFx 導入想定デモ

社労士事務所の5業務を一つの画面で追える自主制作プロトタイプです。顧問先・職員・メール・書類・給与データはすべて架空のサンプルです。

公開URL: https://kazuma1107.github.io/sr-office-demo/

## 現時点の判定

このデモは5項目の**画面構成と業務ルールの試作**です。本番稼働には追加実装と検証が必要です。特に、顧問先ごとの実アクセス制御、電子申請・Outlook・弥生製品との接続、実ファイルの保存、複数人で使う台帳は未実装です。応募先に見せる際は「要件に沿う試作」として説明し、稼働中のシステムとして扱わないでください。

トップ画面には各項目の「試せる操作」と「未実装」を併記しています。各業務画面の先頭に「入力 → この画面で行うこと → 確認できる結果」と、現在の操作・押した後の変化を示す案内があります。案内のボタンは架空データだけを更新します。

## 5つの依頼への対応

| 依頼 | デモで操作できること |
| --- | --- |
| ① 顧問先との情報共有 | 公文書・給与資料・就業規則の公開承認。事務所職員／顧問先担当者の表示切替。顧問先には自社の公開済み資料だけを表示。 |
| ② 公文書の取得・仕分け・保存 | 一括取得の模擬操作、事業所番号による照合、重複保留、判定不能時の職員確認、顧問先別の模擬保存、公開承認。 |
| ③ Outlookのメール・添付整理 | 架空メール4件の分類、添付の模擬保存先、送信元不明の要確認、許可外形式の隔離、判断履歴。 |
| ④ 給与計算と前後作業 | 一度の操作で架空勤怠の検証、3名分の総支給・控除・差引支給の算術計算、前月比較、共有準備。不備データは自動停止し確認事項を表示。 |
| ⑤ 手続・給与の進捗管理 | 顧問先・担当・期限・工程の一覧、絞り込み、状態更新、関連する資料が公開されるまで完了に進めない模擬ルール。 |

## 推奨する操作順

トップの「①からデモを始める」から進みます。各画面の青い案内パネルに、次に押す操作と、押した結果が表示されます。

1. **① 顧問先との資料共有**：職員としてABC社向け就業規則を公開承認し、顧問先担当者表示へ切り替えて「就業規則」タブで確認します。これは画面表示の模擬で、実際のアクセス権ではありません。
2. **② 公文書の取得・仕分け**：架空の4件を取得し、仕分けます。DOC-01だけ公開承認し、重複と所属不明の公文書が自動公開されないことを確認します。
3. **③ Outlookメール整理**：架空メール4件を分類し、保存候補2件・送信元不明1件・許可外形式1件の扱いを確認します。
4. **④ 給与計算の自動化**：「給与計算を自動実行」を一度押します。入力検証、架空の3名分の計算、前月比較、共有準備まで自動で進みます。別シナリオでは重複・社員コード欠落を検出して計算前に停止します。CSV出力は計算後の任意操作です。
5. **⑤ 手続・給与の進捗管理**：案件を次の工程へ進め、担当・期限・次の操作が更新されることを確認します。公開前に進行できない条件もあります。

ブラウザを再読み込みするとデモの状態は初期化されます。

## このデモの給与計算ルール

- 時間外手当 = 残業時間 × 従業員ごとに設定した架空の残業単価
- 総支給額 = 基本給 + 時間外手当 + 通勤手当
- 差引支給額 = 総支給額 − 架空の控除設定額

通常サンプル3名の計算結果は、総支給額913,200円、控除設定額175,500円、差引支給額737,700円です。勤務日数は異常値チェックに使い、固定給の按分には使いません。前月の差引支給額との差が1万円以上なら自動で確認待ちにする、という説明用ルールです。税額・社会保険料の法定計算ではありません。

## デモと本番実装の境界

このサイトは静的HTML、CSS、JavaScriptの操作デモです。SPFxパッケージや稼働中のSharePointではありません。SharePoint、Outlook、Microsoft Graph、電子申請サービス、弥生給与／弥生給与 Nextには接続しません。実際のメール、添付、PDF、給与データ、認証情報は読み込まず、保存・送信もしません。画面上の役割切替はアクセス制御の説明であり、本番の権限制御ではありません。ブラウザを再読み込みすると状態は初期化されます。

給与計算は画面内で実際に算術処理します。ただし、控除額は架空の入力値で、法定の税額・社会保険料を計算しません。出力できるCSVは計算結果を含む汎用サンプルで、弥生製品にそのまま取り込めることを保証しません。製品と版、項目設定、時間単位、CSVレイアウトを確認してから本番用の変換を設計します。

本番化の候補は、SPFx Webパーツ、SharePointサイト／ライブラリとMicrosoft Lists、Power Automate、必要な権限が認められる場合のMicrosoft Graphです。顧問先の分離は画面表示だけに頼らず、テナントの外部共有方針、Entra ID、SharePoint側のアクセス権と失効手順で設計します。電子申請サービスと弥生製品の接続方法は、利用中の製品・契約・提供仕様を調査して確定します。
